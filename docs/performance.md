# 压测记录

压测日期：2026-09-14
压测对象：短链跳转接口 `GET /{shortCode}` —— 全系统唯一的高频路径

---

## 环境

| 项 | 值 |
|---|---|
| CPU | 见下方说明（本机开发环境） |
| JDK | 17.0.12 |
| Spring Boot | 4.0.8 |
| MySQL | 8.0（本机，与服务同机） |
| Redis | 7.4（本机，与服务同机） |
| 服务与压测工具 | **同一台机器** |
| 并发连接 | 150（3 个压测进程 × 50） |
| 持续时间 | 每次 10 秒 |

> **这个数据的定位**：服务端、MySQL、Redis、压测工具跑在同一台机器上，
> 所以数字会互相挤压 —— 它反映的是"这套设计能扛住多少"的量级，
> 不是生产环境的上限。真正上线要分开部署再压一次。

压测工具是自己写的一个 Node 脚本（不引任何依赖），
每个请求新建连接（不复用），所以测的是服务端处理能力而不是连接复用能力。

## 结果

### 一、正常情况（Redis 可用，缓存命中）

| 指标 | 值 |
|---|---|
| **QPS** | **6464** |
| 总请求数 | 64700 |
| 失败 | 0 |
| 平均延迟 | 18 ms |
| P50 | 16 ms |
| P95 | 22 ms |
| **P99** | **35 ms** |

> 单个压测进程只能压出约 2100 QPS，三个进程并行才到 6464 ——
> 说明瓶颈在压测工具（Node 单线程 + 每请求新建连接），
> 服务端还有余量。

### 二、Redis 完全不可用（降级成每次直查 MySQL）

把服务指向一个不存在的 Redis 端口来模拟 Redis 宕机：

| 指标 | 值 |
|---|---|
| **QPS** | **738** |
| 失败 | **0** |
| P99 | ~300 ms |

**关键：失败数是 0。** Redis 挂掉之后跳转功能完全正常，只是变慢了 ——
这正是"缓存是性能优化，不该成为可用性单点"想要的效果。

### 三、对比

| 场景 | QPS | P99 |
|---|---|---|
| 有缓存 | 6464 | 35 ms |
| 无缓存（直查 MySQL） | 738 | ~300 ms |
| **差距** | **约 8.8 倍** | **约 8.6 倍** |

这就是四层防护存在的意义：**缓存把 MySQL 挡在了 88% 的请求之外**。

## 压测过程中发现并修复的问题

**压测不只是拿数字，它还抓出了三个单元测试覆盖不到的 bug。**

### 1. Redis 挂掉时跳转返回 500，而不是降级

`LinkServiceImpl` 里"Redis 挂了自动降级"只判断了 `stringRedisTemplate != null` ——
那只覆盖"没配 Redis"，覆盖不了"配了但连不上"。
而后者才是真正会发生的情况（进程挂了、网络断了、连接池耗尽）。

### 2. 降级路径里回填缓存失败，把整个跳转打回去了

修完第 1 条之后压测仍然是 500。原因是我只给"读缓存"包了 try-catch，
忘了 `queryDbDirect` 末尾的**回填缓存**同样要走 Redis。

数据已经从数据库查出来了，却因为写缓存失败而让整个请求失败 ——
**这让"降级"变成了一句空话**。

### 3. 限流过滤器在 Redis 挂掉时返回 500

`RateLimitFilter` 跑在 DispatcherServlet **之前**，异常没人接得住。
Redis 一挂，它在最前面就把所有跳转打成 500 ——
一个防刷的附加功能把整个服务搞停了。

改成"Redis 不可用时放行"：取舍是**可用性优先于防护**。
反过来（拒绝所有请求）等于因为限流组件挂了而让服务停摆。

## 已知的瓶颈与后续可做的优化

1. **访问明细的异步队列会丢数据**（队列打满时）。上 MQ 解决
2. **定时同步任务是单实例语义**。多实例部署时会重复执行，
   需要分布式锁或改成单实例调度
3. **本机压测数字受工具限制**。要拿到真实上限，
   需要把压测工具放到另一台机器上
4. **没有测"缓存击穿"场景**。可以用一个从没访问过的短码并发压，
   验证互斥锁确实只放了一个线程去查库
5. **没有做长时间稳定性测试**。10 秒的数据看不出内存泄漏、连接池耗尽这类问题

## 复现方式

```bash
# 1. 启动后端（把限流阈值调高，否则压测会被限流）
mvn -pl linkforge-server spring-boot:run \
  -Dspring-boot.run.arguments="--linkforge.ratelimit.max-requests=100000000"

# 2. 建一条短链并预热缓存
CODE=$(curl -s -X POST localhost:8080/api/link \
  -H "Content-Type: application/json" -H "token: <你的token>" \
  -d '{"originalUrl":"https://www.baidu.com"}' | jq -r .data.shortCode)
curl -s -o /dev/null localhost:8080/$CODE

# 3. 压测（3 个进程并行）
for i in 1 2 3; do node load.mjs "$CODE" & done; wait

# 想复现"Redis 不可用"的降级场景，加一个参数即可
#   -Dspring-boot.run.arguments="--spring.data.redis.port=6399"
```
